# 当直くん 雛形記入ガイド（運用者向け）

> 対象: 毎月の当直表を作る運用者。入力Excel雛形（例: `docs/Tochoku.v7_2026.03.1.xlsx`）の書き方と、
> 実行時に出るエラー／警告への対処をまとめる。
> 制約の意味の詳細は `docs/CONSTRAINT_RULES.md`、実行手順は `README.md` を参照。

---

## 0. シート構成の全体像

雛形は **3シート**構成（`sheet1` / `Sheet2` / `Sheet3`）。

| シート | 役割 | 1行 = |
|--------|------|-------|
| `sheet1` | 枠グリッド（誰をどこに入れるかの器）＋カテ当番 | 1日 |
| `Sheet2` | 医師ごとの可否コード | 1日 |
| `Sheet3` | 医師情報（属性・カテ当番チーム・出張・前月累積） | 1医師 |

> **内部名の注意**: コード上は Sheet3 を「医師情報シート（旧称 Sheet4）」として読む。
> Sheet4 が存在しない雛形では Sheet3 が自動的にその役割になる（`main.py` のシート解決ロジック）。
> エラーメッセージに「sheet4」と出たら Sheet3 のことだと読み替えてよい。

---

## 1. sheet1 — 枠グリッド

- **1列目 `Date`**: 対象月の全日を1日単位で連続で並べる（抜け・重複は致命エラー）。
- **B〜Y列（24列）**: 病院・枠の列。列の役割は**列名（ヘッダ）で自動解決**される（位置ズレは警告）。

### 列の役割（標準構成）

| 列 | ヘッダ名（例） | 分類 | カテ制約 |
|----|--------------|------|---------|
| B | 大学平日 | 平日大学系 | 緩和可 |
| C | 大学土曜昼 | 休日大学系 | カテ当番必須 |
| D | 大学土曜夜 | 休日大学系 | カテ当番必須 |
| E | 大学日曜昼 | 休日大学系 | カテ当番必須 |
| F | 大学日曜夜 | 休日大学系 | カテ当番必須 |
| G | 大学祝日昼 | 休日大学系 | カテ当番必須 |
| H | 大学祝日夜 | 休日大学系 | カテ当番必須 |
| I | 支援平日 | 平日大学系 | 緩和可 |
| J | 支援日直 | 平日大学系 | 緩和可 |
| K | 支援当直 | 平日大学系 | 緩和可 |
| L〜Y | 夜間急病, 太陽の国, …, ふたば医療 | 外病院 | カテ当番日は禁止 |
| Z | カテ当番 | （病院列ではない） | チーム当番日コード |

> ヘッダ名は「大学＋平日」「大学＋土曜＋昼」等の**キーワードを全部含む列**として解決される。
> 列を増減・改名すると `⚠️ 列構成が標準と異なります` が出る。意図的な変更でなければ列名を戻す。

### セルへの入力

| 入力 | 意味 |
|------|------|
| `1` | **その日その枠に当直を1つ埋める**（＝ソルバーが医師を割り当てる対象） |
| 医師名（例 `小林`） | **固定割当**。運用者が事前確定した配置。ソルバーは動かさず、制約チェックからも除外する |
| 空欄 / `0` | 枠なし（この日この列は当直不要） |

### Z列「カテ当番」

- その日の**カテ表チームコード**（`A` `B` `C` `D` `E` … / 大型連休は `CC`）を入れる。
- Sheet3 の「カテ当番」列（医師のチーム所属）と突き合わせて、休日大学系（C-H列）の配置可否と外病院禁止を判定する。
- `CC`（大型連休特別シフト）は公平性・重複計算から除外される。
- 空欄はカテ当番なしの日。

## 2. Sheet2 — 可否コード

- **1列目 `Date`**: sheet1 と**同じ日付集合**（過不足があるとエラー/警告）。
- **2列目以降**: 医師名を列見出しにして、日ごとに可否コードを入れる。

### 可否コードの意味

| コード | 意味 | 配置可能な列 |
|--------|------|-------------|
| 空欄 | **可**（＝1と同じ） | B〜Y全て |
| `0` | **不可**（絶対禁忌・その日は割当禁止） | なし |
| `1` | 可 | B〜Y全て |
| `1.2` | 大学優先（大学系B-Kを最低1回必須の準ハード） | B〜Y全て |
| `2` | 大学専用（外病院不可） | B〜Q列のみ |
| `3` | 外病院専用（大学系不可） | L〜Y列のみ |

**注意点:**
- **空欄＝可**。「休み希望」ではない（希望休は `0` で表現する）。
- 全日 `0` の医師は **inactive**（解析から除外・出力には0回で氏名だけ載る）。
- 解釈できない値（`0.5` 等）は「可(1)」扱いになり、実行時に警告が出る。

## 3. Sheet3 — 医師情報（属性・カテ当番・出張・前月累積）

- **1行目**: ヘッダ（`氏名` を含む行が自動検出される。先頭50行以内に必須）。
- **`氏名`**: Sheet2 の医師名と**正規化後に完全一致**する必要がある（後述 §6 NAME_ALIASES）。

### 主要列

| 列 | 意味 | 使われ方 |
|----|------|---------|
| `属性` | `1`=緩和可 / `2`=緩和不可 | SEMI-001（B列カテ表要件）の緩和可否。属性2はカテ表必須（ABS-015） |
| `カテ当番` | 医師のカテチーム所属（`A` `B` `C` `D` `E` 等） | sheet1:Z のチームコードと一致した日にカテ当番。休日大学系(C-H)配置・外病院禁止(ABS-004/013)に使用。空欄=カテなし医師 |
| `出張日` | 曜日（例 `金`） | その曜日の**前日**を自動的に不可(0)扱いにする |
| `出張先` | 参考情報 | 判定には未使用 |
| `全合計` / `大学合計` / `外病院合計` / `平日` / `休日合計` | **前月までの累積回数** | 累計公平性・EXTRA順の参考・出力の累計欄に加算 |
| 以降の病院別列 | 病院別の前月累積 | 出力の累計欄・比率参考 |

> 前月累積は毎月**手で転記せず** `prepare_next_month.py`（§7）で自動加算するのが安全。

---

## 4. 属性・カテ当番・出張・累計の要点

- **属性1 vs 2**: EXTRA枠(+1回)は「属性1優先 → 名簿末尾（若手）から」。属性1は B列カテ表なしを週1回まで許容。
- **カテ当番**: 「保有医師」は当番日のみ大学系(B-K)可・外病院(L-Y)禁止。「カテなし医師」は休日大学系に自由配置可。
- **出張日**: 出張曜日の前日を自動0化（例: 金曜出張 → 木曜が不可）。
- **累計**: 前月までの通算。EXTRA枠は若手末尾に多く出るのが**設計どおり**（累計均等化したい月のみ config の `W_FAIR_CUM > 0`）。

## 5. プリフライトのエラー／警告対応表

実行すると `━━ プリフライト検証 ━━` ブロックが出る。**致命は停止、警告は続行**。

### ❌ 致命（ValueError で停止・修正必須）

| メッセージ（要旨） | 原因 | 対処 |
|-------------------|------|------|
| 必要なシートが見つかりません | sheet1 / Sheet2 / 医師情報シートのどれかが無い/名前違い | シート名を確認（`sheet1` `Sheet2` `Sheet3`） |
| sheet1に重複した日付があります | Date列に同じ日が2回 | 重複行を削除 |
| sheet1の日付に欠落があります | 月内の連続日に抜け | 抜けた日を追加 |
| sheet2に重複した日付があります | Sheet2 Date列に同じ日 | 重複行を削除 |
| sheet1にあってsheet2(可否)に無い日付があります | sheet1 の日が Sheet2 に無い | その日の行を Sheet2 にも追加（無いと全員「可」で黙って処理されるため停止） |
| 総枠数Xが理論上限Yを超えています | gap≥3制約下で埋めきれない枠数 | 枠(sheet1の`1`)を減らす／可否`0`を見直す |

### ⚠️ 警告（続行・確認推奨）

| メッセージ（要旨） | 意味 | 対処 |
|-------------------|------|------|
| sheet2にあってsheet1に無い日付（無視されます） | Sheet2 に余分な日 | 通常は無視で可 |
| 祝日と認識されていない平日に祝日枠があります | 「祝日」列に枠があるが平日扱い | config.HOLIDAYS に祝日を追加、または起動時の `📅 祝日` 表示を確認 |
| sheet2に列が見つからない医師（全日「可(1)」扱い） | Sheet3にいるがSheet2に列が無い医師 | Sheet2 に列を追加（必要なら） |
| sheet2に解釈できないマークがN件（全て「可(1)」扱い） | `0.5` 等の未定義値 | 正しいコード（0/1/1.2/2/3/空欄）に直す |
| sheet4(前月累積)と氏名が一致しない医師 | Sheet3氏名 と Sheet2氏名 の表記ゆれ | §6 の NAME_ALIASES で対応（前月累積が0扱いになる） |

## 6. NAME_ALIASES（氏名の表記ゆれ対応）

氏名突合は **正規化（空白除去）後の完全一致のみ**（同姓医師 佐藤彰/佐藤悠/佐藤勇 の誤マッチ防止のため、部分一致は廃止）。
表記ゆれ（旧字体など）は `config.py` の `NAME_ALIASES` に手動で登録する。

```python
# config.py
# 「sheet2側の表記」→「sheet4(Sheet3)側の表記」（逆向きでも正規化後に突合される）
NAME_ALIASES = {
    "冨田": "富田",
    "斎藤": "齋藤",
}
```

- キー・値とも正規化してから突き合わせるので、どちら向きに書いても動く。
- 「一致N人 / 不一致M人」が起動時に必ず表示される。不一致が出たら該当氏名を確認。

## 7. prepare_next_month.py（翌月雛形の自動生成）

前月の出力から医師別実績を集計し、当月雛形に累積加算して**翌月雛形ドラフト**を作る。
手転記による累計の氏名照合事故（最大の事故源）を避けるためのヘルパー。

```bash
python3 prepare_next_month.py <当月の出力.xlsx> <当月の雛形.xlsx> \
    --pattern 1 -o <翌月雛形ドラフト.xlsx>
```

処理内容:
1. 出力の `pattern_NN` シートから当月実績を集計（全合計/大学(B-K)/外病院(L-Y)/平日/休日）。分類は `main.py::recompute_stats` に一致。
2. 当月雛形をコピーし、Sheet3 の累計列に加算。
3. sheet1 の日付を翌月へ進め、曜日タイプ別の枠数パターンを当月から推定して翌月グリッドを生成（祝日は自動判定）。
4. Sheet2 のマークを全消去（翌月の希望は白紙）。

- `--pattern` は集計元にする出力パターン番号（既定1）。
- 氏名照合は normalize＋完全一致のみ。不一致医師は加算スキップして末尾に警告一覧を表示する。
- 生成物は「ドラフト」。翌月の希望・固定割当・祝日を必ず目視で確認してから使う。
