## 1. なぜ安全に通せるか（設計の核）

避けを叶えても、その人の**当直の総数は変わらない**：

1. **総当直数は目標列（大学目標/外目標）で等式固定**（学年クォータ）。避けても総数は不変。
2. **休日数は公平ペナルティで均される**（`W_FAIR_TOTAL`=30 / 休日spread）。避けの予算をこの公平重みより**小さく**すれば、避けは「**休日↔休日の振替**」でのみ叶い、「休日→平日へダンプして他人の休日を増やす」ことは起きない。
3. 結果、避けを叶えても**他者の負担・公平は悪化しない**。避けは"減免"ではなく"入れ替え"。

これが「叶えられれば叶える」を気前よくやっても壊れない理由。**重みの序列を守ること**が安全性の前提（§5）。

## 2. データ様式：希望シート

- **新規シート「希望」**を雛形に追加（`Sheet2` と同形＝日付行 × 医師列）。
  - `Sheet2` は従来どおり**ハード可否/振り分け専用**（`0`=絶対不可 / `1.2` / `2` / `3` / 空欄）。
    ソフトな避けは Sheet2 に混ぜず、必ず「希望」シートに置く（意味の混濁を防ぐ）。
- **セル値**: `×1` / `×2` / `×3` / 空欄。
  - `×N` = 避けたい強度（1=軽く、3=強く）。空欄=希望なし。
  - **`0`（ハード不可）とは別物**。`0`＝確定予定・休み希望（絶対）、`×N`＝できれば避けたい（ソフト）。
- **段階は 1〜3 のみ**（それ以上は偽の精度）。
- **氏名照合**は `normalize`（空白除去）+ 完全一致のみ（`Sheet3` 名簿と一致必須。ゆれは `config.NAME_ALIASES`）。
- **日付は `Sheet2` と同じ日付集合**。過不足は preflight で警告。
- **未記入の医師＝希望なし**（全日フラット）。

> 「この土日避けたい」＝その土曜と日曜のセルに `×N` を入れる（2セル）。連休なら該当日すべて。

## 3. 重みモデル：予算 ÷ マーク合計（cumulative voting）

各医師に**避け予算 `B_avoid`** を与え、本人が付けた×マークの合計で割る。

- 医師 d の×マーク集合を {(day, N)}、その合計を `S_d = Σ N` とする。
- day に対する**実効ペナルティ** `p_{d,day} = B_avoid × N / S_d`（`S_d > 0` のとき。0なら希望なし）。
- 1人が全部叶っても取れる総ペナルティは **最大 `B_avoid`**（`Σ p = B_avoid`）。マークを増やすほど1件が薄まる＝**多く望むほど通りにくい**。

### 例（`B_avoid = 6`）

| 付け方 | S_d | 各日の実効ペナルティ | 効き |
|--------|-----|--------------------|------|
| `×3` を土日2日だけ | 6 | 各 3.0 | 1週末を強く守れる（ほぼ通る） |
| `×3` を毎週末（8日） | 24 | 各 0.75 | 薄い（無風時のみ） |
| 本命 `×3`（1日）＋おまけ `×1`（4日） | 7 | 本命 2.57 / おまけ 各 0.86 | 本命は守れる／おまけは運次第 |

段階マーク＝**予算の配分（優先順位）**、合計割り＝**希少性**。両立する。

## 4. 目的関数への組み込み

同日重複は禁止（ABS-006）なので、医師 d が day に働くかは `y_{d,day} ∈ {0,1}`
（= その日いずれかの枠に割当）。避けの寄与は目的関数に：

```
objective に  −  Σ_{d, day に×マーク}  p_{d,day} · y_{d,day}
```

を加える（最小化系ならペナルティ加算、最大化系なら符号反転）。これは既存
`SOFT_AVOID_DOCTORS` / `W_SOFT_AVOID`（医師まるごとの軽ペナルティ）の
**「医師×特定日」への一般化＋段階化**であり、実装パターンは同一。

- **CP-SAT**（`solver_cpsat.py`）: `y_{d,day} = Σ_slot x_{d,day,slot}` として線形項を目的に追加。`p` は定数。
- **Greedy**（`main.py`）: 候補スコアリングで、d を day に置く手に `p_{d,day}` のペナルティを加える。
- 両エンジンに**同一項＋テスト**（repo 規律：ソフトは必ず両実装）。

## 5. 重みの序列（キャリブレーション）

避けは「叶えばラッキー」＝**公平を損なわない範囲でだけ効く**よう、既存重みの下に置く：

```
W_FAIR_TOTAL (30)  >  W_FAIR_CUM_HT (20)  >  W_SOFT_AVOID (15)  >  B_avoid (6, 総額)
```

- `B_avoid=6` は1人の避け総額。1件あたりは最大でも `B_avoid`（=6）未満で、公平1単位（20〜30）に届かない。
  → 避けが**休日spreadを1単位でも悪化させるなら公平が勝つ**＝避けは休日↔休日の振替でしか叶わない（§1）。
- 使い始めは `B_avoid` を低く（案6）。信頼が積もったら上げて効きを強められる。
- 既存の `SOFT_AVOID_DOCTORS`（月まるごと減らしたい医師）は**併存**。用途が違う（恒常 vs 単発日）。

## 6. カバー可能性と優先捌き

全員が同じ土日を避けたら誰かは必ず埋めねばならず、**全部は叶わない**。そのとき：

- ペナルティ `p` が**大きい避けほど優先**して回避される。
- `p = B_avoid × N / S_d` なので、**予算を集中させた人（滅多に避けない人）ほど大きい `p`＝優先**。
  頻繁に×を付ける人は `S_d` が大きく `p` が小さいので後回し。
- これは追加ロジック不要でソルバーの最適化が自動的に行う（重みの大小がそのまま優先度）。

## 7. config 項目（案）

```python
# --- 希望ソフト制約 v1（避け専用・日単位） ---
ENABLE_WISH_SHEET = True     # 「希望」シートを読むか（無ければ自動無効）
WISH_AVOID_BUDGET = 6        # B_avoid: 1人あたりの避け予算（総額）。0で無効
WISH_MAX_LEVEL = 3           # ×の最大段階（1..3）
```

- 「希望」シートが無い雛形では**自動的に無効**（後方互換）。
- `WISH_AVOID_BUDGET=0` でも無効。既定を低め（6）にして「使い始めラッキー」を担保。

## 9. プリフライト矛盾検査（`main.py` preflight）

| 検査 | 種別 | 対処 |
|------|------|------|
| 同じ日に `Sheet2=0` と 希望`×` の併記 | 警告 | 0（絶対不可）が優先。×は無視 |
| 同じ日に `×` と（将来の）`◯` 併記 | 致命 | どちらか一方に |
| ×段階が 1..`WISH_MAX_LEVEL` 外（例 `×5`, `×`単独, `◯`） | 警告 | 1..3 に正規化 or 無視して警告 |
| 「希望」シートの医師が名簿に無い | 警告 | NAME_ALIASES で対応（その人の希望は無視） |
| 「希望」シートの日付が Sheet2 と不一致 | 警告 | 揃える |
| 1人の `S_d` が過大（例 >20） | 情報 | 「薄まって実質無効」と表示（乱用の自己抑制が効いている証拠） |

## 10. テスト計画（`tests/test_wish_layer.py`）

- ×マークが**割当を回避させる**（無風の土日で×3の医師が外れる）。
- **予算正規化**の検算（`Σp = B_avoid`、マーク増で各pが減る）。
- **公平が勝つ**（避けが休日spreadを悪化させる状況では避けが叶わない）。
- **総数不変**（避けても大学目標/外目標は守られる＝振替のみ）。
- **カバー不能時の優先**（同一土日を複数人が避け、`S_d` 小の人が優先で叶う）。
- **矛盾検査**（0×併記→×無視、名簿不一致→スキップ+警告）。
- **後方互換**（「希望」シート無し＝従来動作と完全一致）。
- CP-SAT / Greedy 両エンジンで同一結果。
