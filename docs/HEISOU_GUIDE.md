# 併走検証 運用ガイド（当直くん vs 完成版）

> 対象: 当直くんを本番投入する前の「併走検証」期間の運用者。
> 当直くんの出力と、草野先生の手作り完成版を月次で突き合わせ、差を数字で確認する。
> スクリプトの内部仕様は `compare_schedules.py` / `prepare_next_month.py`、
> 雛形の書き方は `TEMPLATE_GUIDE.md` を参照。

---

## 0. 「併走」は2種類ある（混同しない）

| 種別 | 何を比べるか | 状態 |
|------|-------------|------|
| **エンジン併走** | 当直くん内部の CP-SAT（本番）vs Greedy（保険） | 自動・ログ監視で稼働中。退役基準は `ARCHITECTURE_PLAN.md §5` |
| **実運用併走**（本書） | 当直くん出力 vs 草野先生の完成版 | 本書＋`compare_schedules.py` で運用 |

本書は**実運用併走**の手順。目的は「当直くんの解が、実務で通っている完成版と
どれだけ一致するか」を毎月定量化し、乗り換え可否を判断すること。

---

## 1. 形式は1つ：3シート雛形 ＋ pattern グリッド

新しいファイル形式は作らない。入力・出力・実績・繰り越しを**同じグリッド形**で回す。

- **入力** = 3シート（`sheet1` 枠グリッド / `Sheet2` 可否 / `Sheet3` 医師情報）を埋めた月次ファイル（`入力.xlsx`）。
  → 唯一の入力真実。空の状態を「雛形」と呼び、毎月これをコピーして埋める。書き方は `TEMPLATE_GUIDE.md`。
- **出力（当直くん）** = `main.py` が吐く `pattern_01`（スケジュール）＋ `pattern_01_summary`（指標）。
- **実績（完成版）** = 草野先生の採用版を **`pattern_01` シート1枚**にしたもの。
  これが突合対象にも、翌月の累計繰り越し入力にもなる。

### 完成版を「実績ファイル」にする最小手順

草野先生の完成版が「日付行 × 病院列」のグリッドなら、ほぼ変換不要：

1. シート名を **`pattern_01`** にする。
2. **A1 セルを `日付`（または `Date`）** にする（無いと2行目をヘッダ誤認して1日取りこぼす）。
3. 列の並びを雛形 `sheet1` と同じにする（B〜K=大学系、L〜Y=外病院。**位置で分類**、ヘッダ名は照合しない）。
4. セルは医師名（文字列）。空欄・`1`・`○`・`UNASSIGNED` は自動で医師扱いされない。
5. 医師名は雛形 `Sheet3` の氏名と**スペース除去後に完全一致**（旧字体等のゆれは `config.NAME_ALIASES`）。

> `pattern_01` シート以外（Sheet2/Sheet3）は突合でも繰り越しでも読まれないので、完成版側に用意する必要はない。

## 2. フォルダ構成（月1フォルダに集約）

実データは実医師名を含むため `data/` 配下に置く（`.gitignore` 済み。サブフォルダの
`*.xlsx` / `*.md` も除外される）。散らかりを防ぐため月ごとに1フォルダ：

```
data/併走/2026-08/
  入力.xlsx        ← ① 唯一の入力真実（雛形をコピーして埋めたもの。sheet1 / Sheet2 / Sheet3）
  当直くん.xlsx    ← ② main.py 出力（pattern_01 + pattern_01_summary）
  完成版.xlsx      ← ③ 草野先生の採用版を pattern_01 化した実績
  突合.md          ← ④ compare_schedules.py の差分レポート
```

- フォルダ名 = 対象月（`YYYY-MM`）。ファイル名にバージョン等は付けない（フォルダで一意）。
- `data/併走/.gitkeep` だけが git 追跡。中身の実データは全て追跡外。

## 3. 月次サイクル（前々月26日以降に開始）

### ステップ1: 入力を作る
空雛形をコピーし、草野先生の当月インプット（可否・目標回数・固定割当・カテ当番・出張）を
`data/併走/2026-08/入力.xlsx` の sheet1/Sheet2/Sheet3 に反映する。
**当直くんと完成版が同じ入力から出発すること**が公平な突合の前提。

### ステップ2: 当直くんを回す
```bash
python3 main.py data/併走/2026-08/入力.xlsx
```
引数指定で Finder ダイアログを回避できる（`run.sh` は常にダイアログ経路）。
出力は `~/Downloads/入力_v<version>.xlsx`。これを `data/併走/2026-08/当直くん.xlsx` に移す。

### ステップ3: 完成版を実績化
草野先生の完成版を §1 の手順で `data/併走/2026-08/完成版.xlsx`（`pattern_01`）にする。

### ステップ4: 突合する
```bash
python3 compare_schedules.py \
    data/併走/2026-08/当直くん.xlsx \
    data/併走/2026-08/完成版.xlsx \
    --label-a 当直くん --label-b 完成版 \
    -o data/併走/2026-08/突合.md
```
レポート（`突合.md`）に出るもの：
- **サマリー**: 突合スロット数・一致数・**一致率**・日付カバレッジ整合。
- **(a) セル単位の相違**: 同じ日・同じ枠で割当が違うセルの一覧（日付/曜/枠/A/B）。
- **(b) 医師別の回数差**: 大学(B-K)/外(L-Y)/合計の **A−B**（差のある医師のみ、|Δ合計| 降順）。

> A/B は対等。慣例は A=当直くん、B=完成版。差分は「A から見た B との差」。

### ステップ5: 翌月へ繰り越し（累計）
併走中は「実務で採用されるのは完成版」なので、完成版で累計を進める：
```bash
python3 prepare_next_month.py \
    data/併走/2026-08/完成版.xlsx \
    data/併走/2026-08/入力.xlsx \
    -o data/併走/2026-09/入力.xlsx
```
生成物はドラフト（枠数は推定・カテ当番(Z)は空欄・出張/新入医師は要手直し）。
当直くんに乗り換えたら第1引数を `当直くん.xlsx` に替えるだけ。

---

## 4. 読み方の勘所

- **一致率だけを見ない**。差の中身が「公平性の別解（誰でもよい枠の入れ替え）」なのか
  「ルール違反（本来入れない人が入っている）」なのかで意味が違う。前者は許容、後者は入力か
  制約の取りこぼしを疑う。
- **医師別回数差**で `Δ合計` が大きい医師は、目標回数（`Sheet3` の大学目標/外目標）の
  設定ずれか、固定割当・出張の反映漏れの可能性。まず入力を疑う。
- **日付カバレッジ不一致**が出たら、そもそも同じ月・同じ入力から作っていない。突合前に揃える。
- 当直くんの解が制約的に妥当かは `pattern_01_summary` の【スコアサマリー】
  （未割当・gap・重複・外病院累計spread 等）で別途確認する。突合は「完成版との差」だけを見る道具。

---

## 5. 退役判断との関係

`ARCHITECTURE_PLAN.md §5` の Greedy 退役基準は「CP-SAT 自身の健全性（違反0・
フォールバック未発火）」が主。本書の実運用併走は、それと別に
**「人間の完成版との一致度」という実務側の納得材料**を積む位置づけ。
2〜3ヶ月、一致率と差分の性質が安定して問題なければ、乗り換えの実務的根拠になる。
